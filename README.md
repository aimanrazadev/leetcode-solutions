# LeetCode GitHub Sync

A GitHub-only setup that automatically syncs your **accepted LeetCode submissions** into this repository using **GitHub Actions**.

No browser extension is required.

## How it works

```text
You solve a problem on LeetCode
        ↓
LeetCode marks it Accepted
        ↓
GitHub Actions checks every 5 minutes
        ↓
joshcai/leetcode-sync fetches new accepted submissions
        ↓
A new solution is committed to this repository
```

The sync action only adds submissions that have not already been synced. It also keeps the latest accepted solution when multiple accepted submissions for the same problem happen within its duplicate window.

## Repository structure

After your first sync, the repository will look roughly like:

```text
leetcode-github-sync/
├── .github/
│   └── workflows/
│       └── leetcode-sync.yml
├── solutions/
│   ├── 1-two-sum/
│   │   ├── README.md
│   │   └── two-sum.cpp
│   ├── 20-valid-parentheses/
│   │   ├── README.md
│   │   └── valid-parentheses.cpp
│   └── ...
└── README.md
```

The exact filenames and metadata are generated by the sync action.

## Setup

### 1. Create the GitHub repository

Create an empty GitHub repository, for example:

```text
leetcode-solutions
```

You can make it public or private.

### 2. Add this codebase

Push these files to the default branch:

```text
.github/workflows/leetcode-sync.yml
README.md
```

### 3. Add your LeetCode cookies as GitHub Secrets

You need two values from your logged-in LeetCode session:

- `LEETCODE_SESSION`
- `LEETCODE_CSRF_TOKEN`

In GitHub:

```text
Repository
→ Settings
→ Secrets and variables
→ Actions
→ New repository secret
```

Create:

```text
Name: LEETCODE_SESSION
Value: <your LeetCode LEETCODE_SESSION cookie>
```

and:

```text
Name: LEETCODE_CSRF_TOKEN
Value: <your LeetCode csrftoken cookie>
```

### 4. Allow GitHub Actions to write to the repository

Go to:

```text
Settings
→ Actions
→ General
→ Workflow permissions
```

Select:

```text
Read and write permissions
```

Save the setting.

The workflow also declares:

```yaml
permissions:
  contents: write
```

so the built-in GitHub token can create commits.

### 5. Test it manually

Go to:

```text
Actions
→ Sync LeetCode Solutions
→ Run workflow
```

The first run is useful for testing your secrets and permissions.

### 6. Start solving

Solve and submit a LeetCode problem normally.

When the submission is **Accepted**, the GitHub workflow will pick it up on its next scheduled run.

## Important: it is not truly instant

GitHub Actions does not receive a push event from LeetCode here. This setup **polls LeetCode every 5 minutes**.

So the normal behavior is:

```text
Accepted on LeetCode
→ next scheduled workflow
→ solution committed to GitHub
```

GitHub can delay scheduled workflows during periods of high load, so 5 minutes is the target interval, not a guaranteed exact time.

## Security

Never put your LeetCode cookies directly in:

- `leetcode-sync.yml`
- `README.md`
- source files
- committed `.env` files

Use GitHub Actions repository secrets only.

Treat `LEETCODE_SESSION` like a password. Anyone who gets it may be able to act as your logged-in LeetCode session.

## Changing the sync interval

The current workflow uses:

```yaml
schedule:
  - cron: "*/5 * * * *"
```

Examples:

Every 10 minutes:

```yaml
- cron: "*/10 * * * *"
```

Every hour:

```yaml
- cron: "0 * * * *"
```

## Manual sync

Even with the schedule enabled, you can always run it manually from the GitHub Actions page using **Run workflow**.

## Technology

- `joshcai/leetcode-sync@v1.7`

- GitHub's built-in Actions token
